# M13 地图经纬网格验收记录（2026-10-28）

## 一、需求与决策定案（用户逐项确认）

需求演进：初始需求为「地图渲染时叠加经纬线与国际日期变更线（IDL）」→ 调研确认 IDL ≠ 180° 经线（楚科奇/白令海峡 ~169°W、阿留申 ~172.5°E、基里巴斯 1995 东扩至 ~150°W、萨摩亚/托克劳 2011 调整至 ~171°W、汤加/查塔姆绕行段；项目 SP/CP 洋区预存地点多数落在偏离区）→ 用户权衡性价比后**取消 IDL 绘制**，范围收敛为纯经纬线。逐项定案：

| 决策点 | 定案 |
|---|---|
| 密度 | 随 zoom 分档，**预设固定档位表**（用户明确要求：实现前定案，渲染期只查表不适应） |
| 180° 经线 | 普通网格线，不特殊处理 |
| 开关 | 左栏「地图图层」复选框，默认开，会话内内存态（不持久化） |
| 标注 | 紧凑式 `120°E`/`30°S`，`0°`/`180°` 无后缀；贴视口边缘（经线顶边、纬线左边） |
| 更新时机 | moveend/resize 即时重建、**无防抖**（用户前提：重建延迟不能明显——实测为毫秒级同步 DOM 操作） |
| 世界副本 | 副本空间连续区间绘制，天然覆盖 ±180° 之外的世界副本（与 M7f 展开轨迹对齐） |
| 最小档位 | 0.1°（用户定案：更密无意义），z≥10 钳制 |

## 二、预设 zoom→档位表（唯一契约源，E2E 直接断言）

规则：阶梯 `[0.1, 0.2, 0.5, 1, 2, 5, 10, 30]` 度（细→粗升序），取首个满足「邻线像素距 = 档位 × 256·2^z/360 ≥ 48px」的最细档（48px = 最长标注「134.2°E」≈45px + 最小间隙）；z0–1 无档满足 → 回退最粗 30° 且关闭标注；z≥10 钳制 0.1°。Web Mercator 下相邻网格线的像素间距仅取决于 zoom、与视口宽无关（视口只决定可见条数），故档位表以 zoom 为自变量即对所有视口成立——此即「渲染期不根据实时效果确定」的等价实现。

| zoom | 间隔 | 邻线距 px | 标注格式 |
|---|---|---|---|
| 0–1 | 30° | 21 / 43 | 无标注 |
| 2 | 30° | 85 | `150°E` |
| 3 | 10° | 57 | `130°E` |
| 4（默认视图） | 5° | 57 | `135°E` |
| 5 | 5° | 114 | `135°E` |
| 6 | 2° | 91 | `134°E` |
| 7 | 1° | 91 | `134°E` |
| 8 | 0.5° | 91 | `134.5°E` |
| 9 | 0.2° | 73 | `134.2°E` |
| ≥10 | 0.1° | ≥73 | `134.1°E` |

## 三、实现要点

- `app.js` M13 段（app.js:150–263）：`GRATICULE_*` 常量 + `graticuleInterval`/`graticuleLatLabel`/`graticuleLonLabel`（副本经度经 `toSignedLon` 转 signed 口径）+ `renderGraticule`（清空重画：经线逐条竖线、纬线单段横线，索引步进避免 0.1 档浮点漂移）；独立 pane `graticule`（z=350：瓦片之上、全部矢量叠加之下——moveend 全量重建不改变层序）与 `graticule-labels`（z=450：矢量之上、交互标记 600 之下）+ 专用 `L.svg` renderer（padding=1 与线绘制边距一致；SVG 保留逐线 path DOM 供 E2E 断言，Canvas 无此能力故不仿 statsCircleRenderer）；渲染器容器 `pointerEvents: none`（沿 statsCircleRenderer 先例防拦截空白点击）；视口角点反投影得副本空间连续经/纬区间并两侧各外扩一个视口（覆盖 worldCopyJump 跳回前的拖拽过程）；标注按容器坐标过滤至当前视口、顶边起点避开左上缩放控件；开关关闭时重建短路；`window.__map` 测试钩子（跨副本视图无 DOM 操作手段）；开关接线在 app.js:1786。
- `index.html`：「地图图层」小节（`#graticule-toggle` 默认 checked）+ `?v=m12→m13` 两处（style.css/app.js）及注释同步（M8-R1 纪律）。
- `style.css`：`.graticule-line`（白 45%、1px、pointer-events none）/ `.graticule-label`（10px 白字深色光晕）/ `.inline-check`（行内复选框）。
- `tests/test_ui_e2e.py`：新增 4 项（见 §五）；M7f 探针选择器收窄（见 §六.2）。

## 六、问题处置（3 项，均实测复现与修复）

1. **档位选取方向反了**：`graticuleInterval` 初版在粗→细排序数组上「取首个满足 ≥48px 的档」= 最粗档 30°。现象：fitBounds z6 视图仅 3 线 2 标注（`180°`/`30°N`，即 30° 档在该视野的全部产物）；tier 测试因 30 恰好同时 mod 2 / mod 5 而**空过**。修复：阶梯改为细→粗升序、取首个满足档；全档位对表逐档复核（z2→30/z3→10/z4→5/z5→5/z6→2/z7→1/z8→0.5/z9→0.2/z≥10→0.1）；
2. **M7f 探针污染**：`_max_path_wrap_ratio` 扫描 `#map svg path[d]` 全体，新增纬线（两点横线）maxStep/span 恒为 1 → 两项反经线回归假阳失败。修复：选择器排除 `.graticule-line`（探针语义本就是轨迹族折线，参考层不属其分母；docstring 同步注明）；
3. **屏外线可见性等待误判**：`.first.wait_for()` 等待可见性，而 DOM 序首条线是边距外扩的屏外经线（x=−459，被 SVG 裁剪为 hidden）→ 超时。修复：改 `wait_for_function` DOM 计数等待，与计数断言口径一致。

## 七、单向依赖复核

M13 仅依赖 M2/M3 地图基建（`L.map`/layerGroup 模式）与 M7f 既有函数 `toSignedLon`；core/service/api 零改动；无前向引用（M13 为最新里程碑）。对既有资产的唯一触碰为 M7f 探针选择器收窄（测试侧，语义见 §六.2，反经线回归本体断言未变）。

## 八、遗留观察

- 有头浏览器人工复验（拖拽跟手性、标注边缘观感、不同底图亮度下的可读性）建议用户日常使用时顺带确认；无头 E2E 与像素核验已覆盖几何、层级与配色正确性；
- z0–1 多世界视图不显示标注为预设规则（邻线距不足）；如实际使用需要可再议；
- 顶边标注起点以 48px 避让左上缩放控件；若未来地图控件位置变动，需同步 `GRATICULE_ZOOM_CONTROL_CLEAR_PX`。
