# 反经线（跨 180° 经线）绘制缺陷修复验收记录（2026-10-18）

## 1. 问题来源与复现方式

- **用户试用反馈**：绘制成员轨迹时，气旋前后时次跨过 180° 经线，连线不走最短方向，
  而是反向延伸到另一侧（经 0° 经线绕行整幅地图）。
- **复现方式**：合成跨经线 CSV（WNC 真实导出的 0–360° 经度约定，气旋自西向东跨 180°），
  走完整真实链路复现：`DatasetStore` 导入 → `GET /api/datasets/{id}/tracks` → 浏览器打开工作台，
  读取成员线/均值轨迹 SVG path 实际几何。复现脚本与临时服务均在系统临时目录，
  未触碰项目 `uploads/`。

## 2. 根因（已实证）

1. **数据层无错**：`core.geo.signed_longitude` 把 0–360° 归一到 [−180,180]，
   `service.queries.track_rows` 的 `lon_signed` 语义正确（181.9 → −178.1）。
2. 前端 `pointCoords()` 优先取 `lon_signed` 作为 `L.polyline` 顶点，
   组内序列含 ±180 跳变（如 lead 24→48 的 179.0 → −178.1，Δ = −356.1°）。
3. **根因**：Leaflet 1.9.4 折线对反经线无感知——顶点各自经 EPSG:3857 投影
   （x 与经度线性），相邻顶点在**投影平面内连直线**。179.0 与 −178.1 分别投影在
   世界副本右端/左端，直线横穿整幅地图（经 0° 绕行 ~356°，占世界宽 ~99%），
   而最短路径仅 ~2.9°。
4. **附带效应**：`map.fitBounds` 的包围盒同时含 ±180 两侧点 → 视图被拉到近全球尺度。

修复前实测证据（内置浏览器，第一版平直合成数据）：

| 证据 | 数值 |
|---|---|
| 成员线 path | `M211 350L29 350`（横穿整图的水平线） |
| 均值轨迹 path | `M245 351L247 351L-7 350L-5 349`（顶点 x 247 → −7 跳变，画到视口外） |
| Leaflet 投影（zoom 4，世界 4096px） | lon 179.2 → x=4087，lon −178.2 → x=20；绘制段宽 4066px（99.3%），最短路径 ~31px |

## 3. 修复方案（纯前端渲染层；core/service/api 与契约不动）

`typhoon_track/web/static/app.js`：

1. 新增 `nearestLon(lon, refLon)` / `unwrapCoords(coords)`：组内顶点经度逐点展开为
   连续序列（相邻差 ≤ 180°，如 179.0 → 181.9 而非 −178.1）；超出 ±180 的经度由 Leaflet
   自然投影到相邻世界副本，连线即沿最短方向跨越。
2. **同组点/线/包围盒共用同一份展开坐标**（避免线画在一个世界副本、点落在另一个副本）：
   - 成员主线与高亮光晕线（`render`）；
   - 单成员模式 circleMarker（行与坐标配对后逐位取用）；
   - 观测叠加线与观测点（`render` obsGroups）；
   - 均值轨迹、时次点、当前时次标记与 p 概率圆、关键时次圆（`renderStatsLayer`，
     `drawnCenters` 与 `drawnLeads` 逐位对应，`lastStatsLayout` 一并携带供 zoom 后重算）；
   - 引线标签切向 `offsetLatLng` 改收展开坐标点（`neighborPoints`），跨经线时切向不反向；
   - `fitBounds` 的 bounds。
3. `geoCirclePoints` 圆环顶点相对圆心展开：跨经线概率圆/参考圆不再断裂成
   横穿世界的多边形（`destinationPoint` 归一回 ±180 所致）。

## 5. 已知边界（非本次回归）

- `fitBounds` 以各组**独立展开**坐标求并：若同屏多条轨迹分居 ±180 两侧且各自不跨线
  （如 −170 与 +184 同屏），包围盒仍可能接近全球（修复前 signed 语义亦然）。
- 弹窗文本仍显示 signed 经度（数据规范口径），地图几何用展开经度（渲染口径），两者等价。
- `worldCopyJump` 拖拽行为不变。
