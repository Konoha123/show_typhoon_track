# M10 服务简单入口与 configs 目录统一验收记录（2026-10-22）

## 1. 需求背景与目标

- 用户需求：为项目主服务增加一层**薄封装**，支持 `python app.py` 的简单方式运行；
  可接受新增配置文件（监听 ip/port）；配置文件解析基于 **pydantic JSON**。
- 目标：① 根目录简单入口；② 运行时配置统一收敛到 `configs/` 目录管理。

## 2. 环境与验收方式

- 环境：`show-typhoon-track`（Python 3.13.16，pydantic 2.14.1，uvicorn 0.54.0）。
- 验收方式：规划期只读调查（配置盘点、契约/工具影响核实）+ 分层验证（L0–L3、L5 全量）
  + `python app.py` 真实启动 curl 冒烟与缺文件行为核验（L6）。

## 3. 前置调查结论

1. **configs/ 统一可行性**（规划期逐项盘点）：
   - 根目录真正意义上的"运行时配置"仅两份：瓦片（toml，M3 落地）与服务监听（json，本里程碑新增）；
   - `places/places.csv`（用户手工维护的地点数据）与 `uploads/`（页面导入的原始 CSV）属
     运行时**数据**而非配置，不迁入（与 AGENTS §5 盘点结论一致）；
   - `demo_src` 导出产物（`selected*.csv`）与下载目录（`ensemble/` 等）为工具产物，非配置；
   - 结论：双配置文件并存、各管一域，统一放根目录 `configs/`，不强行统一格式。
2. **根目录 app.py 的工具链影响核实**：
   - importlinter：`.importlinter` 的 `root_packages` 只含 `typhoon_track`，根脚本在契约外，
     不产生违例（配置解析模型放包内 `api/server_config.py`，属 api 层，契约覆盖）；
   - pyright：`pyrightconfig.json` `include: ["."]` 自动纳入根脚本，`pyright` 实跑 0 告警；
   - deptry：根脚本 import 的 uvicorn（requirements.txt 已声明）与 typhoon_track
     （`known_first_party`）均合法；app.py 直接 import uvicorn 后，pyproject 中 uvicorn 的
     DEP002（声明未使用）豁免随之移除，deptry 复核无告警；
   - pytest：`testpaths = tests demo_src`，根脚本不进收集。
3. **pydantic JSON 解析**：pydantic>=2.7 已在 `requirements.txt`（api/schemas.py 已用），
   用 `BaseModel + json.loads + model_validate` 即可，不引入 pydantic-settings、不加新依赖。

## 4. 口径（已经用户逐项确认）

| 决策点 | 口径 |
|---|---|
| 双配置文件 | 并存、各管一域：`configs/tiles.toml`（瓦片）+ `configs/server.json`（服务监听） |
| configs 位置 | 仓库根目录（与 `places/`、`uploads/` 平级；`PROJECT_ROOT` 锚点复用） |
| server.json 缺失 | **报错退出**（退出码 1，与瓦片配置"缺文件即报错"口径一致），不回退默认值、不自动生成模板 |
| host 校验 | 仅非空（uvicorn 自身解析失败会报错） |
| port 校验 | ∈ [1, 65535]（pydantic Field ge/le） |
| `python -m typhoon_track` | 仍为 CSV CLI（`__main__.py`），与 `python app.py` 并列记载于文档 |

## 7. 端到端冒烟（python app.py）

- `python app.py`（仓库默认 `configs/server.json`）：
  - 启动日志 `Uvicorn running on http://127.0.0.1:8000`（host/port 均来自配置文件）；
  - `GET /` → 200，页面含瓦片 URL（`server.arcgisonline.com/.../tile/{z}/{y}/{x}`）；
  - `GET /static/style.css` → 200。
- 缺文件行为核验：临时移走 `configs/server.json` 再运行 `python app.py`：
  - stderr traceback `ValueError: 服务配置文件不存在: .../configs/server.json`；
  - 退出码 1（`$?` 经 PIPESTATUS 核实，排除管道假象）；文件已复原。
- 非法配置防错（L5 单测覆盖）：非法 JSON（中文报错含行号）、port 0/65536 越界、
  host 空白、缺 host 字段均被拒绝。

## 10. 遗留观察

- `python app.py` 不支持命令行参数覆盖（如临时换端口仍用
  `python -m uvicorn typhoon_track.api.app:app --port <n>`，两入口并列记载）；
  参数化需求出现时再评估，暂不实现。
- `configs/server.json` 目前仅 host/port 两键；后续若增加服务级配置（如日志级别），
  沿用 `ServerConfig` 扩展，不另开新文件。
