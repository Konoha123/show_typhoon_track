# M14 打包方案验收记录（PyInstaller onedir）

日期：2026-11-11 ｜ 关键提交：M14a `0b04cff`（冻结感知路径与浏览器辅助）、M14b（本记录与打包资产）

## 一、目标与决策

目标：双击可执行文件即启动 Web 服务并自动打开浏览器，免去 Python 环境与命令行；与 `python app.py` 的行为差异仅此一项。

| 决策点 | 结论 | 理由 |
|---|---|---|
| 打包形态 | **onedir**（`dist/typhoon-track/`） | pandas+numpy 冻结包 158M，onefile 每次启动需解压到临时目录、启动慢；onedir 启动快、数据稳定 |
| configs 位置 | **外置**于产物目录（构建后复制，可编辑） | 与源码运行"配置文件"语义一致，打包后仍可改端口/瓦片源（冒烟第 7 项验证生效） |
| places.csv | 外置（模板 `places.example.csv` 随分发，缺文件优雅降级） | 用户手工维护数据；降级路径 M6 起既有 |
| uploads/ | 运行时在可执行文件旁自动创建 | onefile 临时目录会丢数据的根因在 onedir 下自然消解（M14a 冻结感知路径） |
| 控制台窗口 | **保留**（console=True） | uvicorn 日志与出错诊断可见 |
| spec 文件 | **不入库**（`.gitignore` 增 `*.spec`） | 用户要求；打包配方单源收敛于 `scripts/build_exe.py`，spec 为该脚本按需生成的构建过程产物 |
| 依赖裁剪 | excludes：uvloop/httptools/watchfiles/websockets/tkinter | uvicorn 自动回退 asyncio/h11，行为等价、体积与兼容风险双降 |

## 二、实现要点

- **M14a（`0b04cff`）**：`api/app.py` 新增 `default_project_root()`——frozen 时 = `sys.executable` 所在目录（configs/places/uploads 外置于此），源码运行 = 仓库根（行为不变）；根 `app.py` 收敛 `main()` + `__main__` 守卫，仅 `sys.frozen` 时后台 daemon 线程 socket 轮询端口就绪（15s 超时）后 `webbrowser.open`，通配 host（0.0.0.0/::）映射 127.0.0.1，失败打印 URL 兜底。测试 +10（`tests/test_frozen_paths.py`）。
- **M14b（本提交）**：`scripts/build_exe.py` 内嵌全部打包配置（入口 `app.py`、name `typhoon-track`、datas = `typhoon_track/web/templates` + `static`（含 Leaflet/uPlot vendor，约 320K）、hiddenimports = `typhoon_track.api.app`（uvicorn.run 字符串导入兜底）+ `python_multipart`/`multipart`（模块名迁移期双写）、excludes 见上表），生成 `typhoon-track.spec` 后调 `python -m PyInstaller --noconfirm --clean`，复制 `configs/` 与 `places/places.example.csv` 至产物目录，产物自检（exe、`_internal` 内 web 资源、外置文件）。
- `requirements-dev.txt` 增 `pyinstaller>=6.0`（实际安装 6.22.3，hooks-contrib 2026.10）。

## 三、构建步骤

### Linux（本机已验证）

```bash
conda activate show-typhoon-track
python -m pip install -r requirements-dev.txt    # 含 pyinstaller>=6.0
python scripts/build_exe.py
# 产物 dist/typhoon-track/（158M），运行：./dist/typhoon-track/typhoon-track
```

### Windows（需在 Windows 机器执行；PyInstaller 不交叉编译）

```bat
:: Python 3.13+（venv 或 conda 均可；只需运行时依赖 + pyinstaller，无需 dev 全家）
python -m pip install -r requirements.txt "pyinstaller>=6.0"
python scripts\build_exe.py
:: 产物 dist\typhoon-track\typhoon-track.exe，双击运行
```

脚本与 spec 模板均无平台分支（pathlib + 相对路径），Windows 侧预期直接可用；**本机无法产出/验证 Windows exe**，首次实机构建后如有问题按本记录"问题处置"格式回填。

## 五、问题处置

1. **`pkill -f` 自匹配**：冒烟中 `pkill -f "dist/typhoon-track/typhoon-track"` 匹配到命令自身所在 shell 将其杀死（`Unknown: ChildProcess.kill`）。处置：改按 PID 直杀或模式字符类（`trac[k]`）打断自匹配；另注意 setsid 启动的进程 cmdline 为相对路径 `./typhoon-track`，pgrep 全路径模式匹配不到，以 `ss -tlnp` 端口定位最可靠。
2. **后台进程随工具会话被终止**：普通 `nohup ... &` 启动的服务在 shell 会话超时终止时一并被杀。处置：`setsid nohup ... < /dev/null &` 脱离会话后进程存活。
3. **脚本初版笔误**：`build_exe.py` 收尾 print 含无意义三元表达式、`_verify` 内重复推导 exe 名——已在提交前修正为 `main` 内单点计算并传参。

## 六、已知限制与遗留观察

- Windows 产物未在本机验证（见 §三）；无签名 exe 可能触发 SmartScreen/杀软告警，属分发层面问题。
- 冻结路径仅支持 onedir（`sys.executable` 旁）；onefile 未实现（用户决策弃，如需启用须拆分只读资源根 `_MEIPASS` 与可写数据根）。
- onedir 产物 158M，分发需整目录打包（如 zip）；`build/`（中间产物）与 `dist/`、`*.spec` 均被 `.gitignore` 排除，不入库。
- 浏览器打开时机为端口就绪即开（约 1s 内），未等待 uvicorn "Application startup complete" 事件——socket 可连即服务可答，实测无竞态。
